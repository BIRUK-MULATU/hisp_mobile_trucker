Purpose. This checklist walks a tester through every user-facing feature of the RDHIS2 Mobile Tracker. Each row is a single test case with the steps to perform and the expected result. Mark Pass or Fail, and record the actual behaviour, screenshots or defect IDs in the Notes column.

How to use it.

  • Work top to bottom within each section; sections are independent, so you may split them across testers.
  • A case passes only when the observed result matches the expected result in full.
  • For any fail, capture a screenshot, note the exact on-screen text and log a defect ID.
  • Re-test offline-first behaviour explicitly (airplane mode) — it is central to this app.
  • Use a staging/test DHIS2 server and non-production accounts. Do not enter real patient data.
